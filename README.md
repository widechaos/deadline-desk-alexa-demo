# Deadline Desk

A personal return-deadline workspace: keep evidence, prioritize a purchase, prepare a return, and record what happened. This is an **independent Alexa+ web simulation**, not a deployed Alexa Skill or a merchant integration.

## Run locally

Tested on macOS Apple Silicon with Node.js 22+, llama.cpp, whisper.cpp and FFmpeg. The language model needs roughly 2.5 GB of disk space, plus 150 MB for speech recognition. First-time setup needs Internet access; inference uses local models and requires no paid API or account.

```sh
brew install llama.cpp whisper.cpp ffmpeg
mkdir -p models
curl -L --fail -o models/Qwen3-4B-Q4_K_M.gguf https://huggingface.co/Qwen/Qwen3-4B-GGUF/resolve/main/Qwen3-4B-Q4_K_M.gguf
curl -L --fail -o models/ggml-base.en.bin https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.en.bin
npm run dev
```

Open http://127.0.0.1:4176 after the model finishes loading. The launcher starts both servers and creates a local random key if absent. Ctrl+C stops them. Keep ports 4176 and 8096 free. Models, keys and recordings are excluded from Git. Other platforms need the same executables on PATH; they have not been tested.

[Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B-GGUF) is Apache-2.0 according to its model card. [whisper.cpp](https://github.com/ggml-org/whisper.cpp) supplies local transcription. Model weights are downloaded separately, not redistributed here. The included synthetic voice recordings were generated for this prototype with [Kokoro v1.0](https://huggingface.co/hexgrad/Kokoro-82M), an Apache-2.0 model, using the MIT-licensed [kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx) runtime. See test-fixtures/voice/README.md for provenance.

No npm runtime dependencies are needed. For development formatting, use `npm ci`. Run `npm test` for boundary checks; `npm run eval:intents` requires the running local servers. `node scripts/eval-voice.mjs` tests six included synthetic English recordings. Test output is saved under the ignored evidence directory.

## What is real

The local language model suggests receipt fields with exact source quotes and routes requests into one of seven constrained intents. Quote checks reject invented delivery evidence and conflicting policy windows; the user still reviews every field before saving. Deterministic tools calculate dates, prioritize cases, prepare checklists, draft requests, and produce calendar files. Tool text is generated by application templates; this is not an open-ended conversational LLM. Completion always asks for confirmation, with reopening available. Cases persist in browser localStorage.

Three fictional receipts are seeded on first use. Delivery dates are relative to that first day and remain unchanged after saving. Users can add reviewed receipt and policy text with explicit delivery and window fields. Calculation uses delivery + calendar days; exclusions, inclusive counting rules, and refund eligibility must be checked with the merchant. The amount is the purchase value, not verified savings or guaranteed refunds.

## Voice and privacy

Microphone input needs browser permission. Press the microphone again to stop; recording also stops after 30 seconds. Audio is sent only to the local app and transcribed with Whisper base.en. Temporary server audio files are deleted after processing. The transcript is placed in the request field for review; it is **not automatically sent to the assistant**. Text input and a clearly labelled synthetic recording offer alternatives. Read-aloud uses the browser's available English speech-synthesis voice; voice availability varies by device.

Six clean synthetic recordings passed transcription-to-intent checks. Actual browser testing verified transcript review, assistant routing, and read-aloud play/stop controls. Human microphone quality, accents and background noise remain unverified. This is an English speech prototype.

A further [synthetic voice stress test](docs/voice-stress.md) used 12 StepFun-generated clips with varied delivery instructions. All reached the expected intents; nine transcripts matched the requested text after normalization. Two repeated a sentence and one omitted a filler. No human participants were involved, and the requested accent styles were not independently validated.

Both servers bind only to 127.0.0.1. Do not expose them publicly. Receipts stay in browser storage; exports leave the browser only when requested. ICS export downloads a file; it does not create an event in a connected calendar account. Message drafts are not sent.

## Prototype limits

Image/PDF extraction, general policy exception interpretation, native Alexa integration, email/calendar account connections, and real-user validation are not complete. The 4B model classified 20 of 20 held-out intent examples correctly; this small benchmark is not a general accuracy claim. Local model failures are shown; no fake successful answers are substituted.

## Demo flow

1. Try the synthetic voice recording; review its transcript and ask “What should I return first?”
2. Open receipt/policy evidence; ask “Why is this the deadline?”
3. Prepare a return checklist and draft a merchant message.
4. Download the calendar reminder and review it before importing.
5. Record the completed return, reload to see persisted state, then reopen the case.
6. Paste an ambiguous receipt/policy: missing delivery and conflicting windows stay blank for review.
